# ShiroGifts

Telegram Mini App для кейсов, коллекции подарков и NFT, апгрейдов и мини-игры Crash. Интерфейс находится в `frontend/index.html`, сервер — Node.js 20+ / Express, данные — PostgreSQL.

## Реализованные возможности

- Проверка Telegram Mini App `initData` на сервере и привязка действий к Telegram ID.
- Баланс Stars через журнал операций `wallet_ledger`.
- Пополнение через Telegram Stars: invoice, проверка `pre_checkout_query`, зачисление только после `successful_payment` и защита от повторного charge ID.
- Кейсы с серверным выбором результата, списанием баланса и идемпотентным request ID.
- Бесплатный кейс подписчика с проверкой через `getChatMember` и кулдауном.
- Апгрейды с серверной вероятностью и блокировкой исходного предмета.
- Crash с серверным раундом, блокировкой ставок и проверяемым хешем seed.
- Продажа предметов, заявки на вывод NFT и отправка обычных Telegram-подарков через Bot API.
- Если на балансе бота недостаточно Stars, вывод обычного подарка переходит в очередь администратора. Состояние отправки сохраняется отдельно, чтобы не повторять отправку автоматически после неопределённого сбоя.
- Промокоды, ежедневная награда, рефералы и административные инструменты.
- Настройка уведомлений владельцу в Telegram о событиях с подарками.

## Запуск

Требуются Node.js 20+ и PostgreSQL.

```bash
npm install
cp .env.example .env
npm start
```

При старте сервер автоматически применяет миграции PostgreSQL. Проверка состояния: `/api/health`.

## Переменные окружения

Скопируйте `.env.example` и задайте значения:

- `PORT` — порт HTTP-сервера.
- `DATABASE_URL` — строка подключения PostgreSQL.
- `DATABASE_SSL` — `true`, если провайдер требует TLS с отключённой проверкой сертификата.
- `TELEGRAM_BOT_TOKEN` — токен бота; хранить только в секретах Railway.
- `TELEGRAM_BOT_USERNAME` — username бота без @.
- `TELEGRAM_WEBHOOK_SECRET` — случайный секрет для защиты webhook.
- `WEBAPP_URL` — публичный HTTPS URL приложения; используется при регистрации webhook.
- `ADMIN_TELEGRAM_IDS` — Telegram ID администраторов через запятую.
- `TELEGRAM_CHANNEL_USERNAME` или `TELEGRAM_CHANNEL_ID` — канал для проверки подписки.

Не добавляйте реальные секреты в GitHub или клиентский HTML.

## Telegram и Railway

1. Подключите PostgreSQL к сервису приложения и задайте переменные окружения.
2. Укажите `WEBAPP_URL` равным публичному URL Railway.
3. При наличии `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET` и `WEBAPP_URL` сервер регистрирует webhook при запуске.
4. В BotFather укажите Mini App URL: `https://t.me/ShiroGiftsBot/ShiroNft` (если short name Mini App изменится, обновите ссылку в коде и сообщениях бота).
5. Добавьте бота администратором канала, если используется проверка подписки.

## Важные ограничения

- Переключатель режима записи и повышенные демонстрационные шансы работают только в интерфейсе владельца и не должны изменять серверный баланс или реальный инвентарь.
- Подтверждение возраста в приложении является самоподтверждением, а не независимой проверкой возраста.
- Перед публичным запуском платных случайных механик и вывода подарков необходимы юридическая проверка применимых правил, проверка настроек Telegram Bot API, мониторинг, резервное копирование PostgreSQL и тестирование реальных платежей/выводов в контролируемой среде.
- Для критичных операций используйте логи Railway и проверяйте результат транзакции, а не только состояние интерфейса.

## Проверки

В репозитории нет отдельного набора автоматических интеграционных тестов. Перед релизом необходимо проверить в Telegram:
- пополнение Stars и повторную доставку webhook;
- открытие кейсов при параллельных запросах;
- апгрейд и повторный request ID;
- ставки, cashout и восстановление Crash после перезапуска;
- вывод подарка при достаточном и недостаточном балансе бота;
- восстановление зависшей заявки из административной панели;
- включение и отключение уведомлений владельцу.
